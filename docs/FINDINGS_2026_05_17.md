## Part I: What Was Attempted and What Died

### 1. Qwen3.6-35B-A3B on M1 8GB

**Status**: FROZEN. Component-level verification passed, end-to-end generation never produced correct output.

**Root cause**: Multiple independent error sources (q4 quantization drift, custom DeltaNet/GQA/MoE implementations, residual accumulation) create a compound attractor collapse. Individual components were verified correct (DeltaNet cos=1.000000 vs HF, GQA cos=0.9999), but the 40-layer stacked error exceeds the model's signal-to-noise threshold.

**Lesson**: Component verification ≠ system verification. The research platform had too many independent error sources to distinguish theory failure from implementation bug.

### 2. Koopman Linear Prediction (REVISED 2026-05-17 23:00)

**Hypothesis**: z_{t+1} ≈ A @ z_t where z_t is the PCA-projected delta Δh_t.

**Initial result (single prompt, n=30)**: DEAD. cos = -0.03.
**Revised result (cross-validated, 5 train + 2 test prompts, n=175)**: PARTIALLY VIABLE. cos = 0.47.

The initial experiment had insufficient data (30 deltas, single prompt). The cross-validated experiment with 125 training deltas and 50 test deltas shows the linear operator has significant predictive power at 1-step horizon.

| Metric | Old (single prompt) | New (cross-validated) |
|--------|---------------------|----------------------|
| z persistence (z_{t+1} ≈ z_t) | cos = -0.45 (anti-correlated) | cos = -0.42 (anti-correlated) |
| Linear A@z_t | cos = -0.03 | **cos = 0.47** |
| GRU nonlinear | — | cos = 0.22 (overfits) |
| Multi-step horizon (A^n @ z) | — | cos ≈ 0.00 (all horizons) |

**Lesson**: The 1-step linear predictor IS viable at cos=0.47. This enables warm-start, prefetch, and budget estimation. However, the multi-step horizon prediction fails completely (A^n @ z_t does not predict z_{t+n}). The dynamics are **1-step partially forecastable, multi-step not forecastable**. The Koopman operator is local (1-step) but does not compose across time.

### 3. Hidden State Anchoring

**Hypothesis**: Cache h_t as an anchor and apply low-rank delta updates.

**Result**: DEAD. cos(h_t, h_{t-1}) ≈ 0. The hidden state rotates rapidly (spherical steering). It is NOT a stable reference point.

**Lesson**: h_t is a phase point in motion, not a state to be cached. KV cache works for attention algebra, not as a semantic state representation.

### 4. Re-Anchor Interval

**Hypothesis**: Full recompute every N tokens can prevent drift.

**Result**: Drift is immediate (step 1: relative drift 0.8-0.9) and saturates quickly (2-3 steps). The drift magnitude is independent of re-anchor interval.

**Lesson**: The hidden state is fundamentally volatile. Anchoring strategies that rely on state stability are structurally invalid.

## Part II: What Survived and Works

### 1. Delta PCA Compression

**Verified across 5 prompts, 150 tokens**:
- 64 dimensions capture 92% of total Δh energy
- 10 dimensions capture 50% of total Δh energy
- Effective rank (90%): 58 dims (2.8% of 2048D)
- Effective rank (95%): 73 dims (3.6% of 2048D)
- Effective rank (99%): 97 dims (4.7% of 2048D)

**Implication**: State transitions are highly compressible for I/O purposes. This enables low-rank transport representations even though the temporal dynamics are not predictable.

### 2. Koopman Layer Collapse (Static Skip)

**TinyLlama-1.1B (Family A, Dense)**:
- Safe fusion ratio: 0.50 (stride=2, skip 27% of ISOMETRIC attention layers)
- Speed improvement: 15% (7.3s → 6.2s for 12 tokens)
- Output quality: maintained across all tested prompts
- Degeneration boundary: fusion=0.33 (stride=3, 36% skip) → repetition collapse

**Mechanism**: Phase III (ISOMETRIC, L3-L13) has J≈I (near-identity Jacobian). Every other layer can be identity-skipped without semantic degradation.

### 3. Heterogeneous Token Execution

**Verified on TinyLlama**:
- Token classification: STABLE / DEFAULT / STEERING / TRANSITION / REPETITIVE
- 54-68% of attention layers skipped across all tokens
- Output quality maintained
- Speed improvement limited by MLX framework overhead (Python dispatch, lazy graph)

**Key insight**: Not all tokens need the same compute budget. Stable tokens (confident, low steering) can skip 50%+ of layers. Steering tokens need full compute.

**Framework bottleneck**: MLX lazy evaluation means skipped layers still create graph nodes. The theoretical speedup is 2-3x higher than measured 0-15% on MLX. Rust executor (as demonstrated with Qwen3.6 DeltaNet collapse: 450ms→0ms) would realize the theoretical gain.

### 4. LLM Scheduler Architecture

**Implemented in `runtime/os/`**:
- `Scheduler`: phase-aware policy table, state tracking, dynamic fusion
- `PrecisionGovernor`: DVFS-like precision control (designed, limited by MLX framework)
- `OSLLM`: Scheduler-driven LLM wrapper with monkey-patched forward layer
- Token classification: entropy + steering → STABLE/DEFAULT/STEERING/TRANSITION/REPETITIVE
- Temporal stride: staggered compute across tokens with steering gate
- State-aware dynamic fusion: entropy → fusion ratio modulation

### 5. Phase-Compliant Baseline (no OS)

**TinyLlama-1.1B-Chat on M1 8GB (MLX)**:
- Baseline: 4.9 tok/s forward, 1.6-1.8 tok/s end-to-end
- Model weights: 2.2GB f16
- Verified correct output on all test prompts
- 22 layers, 2048 dim, 32 heads, 4 KV heads (GQA), SwiGLU FFN

## Part III: Theoretical Conclusions

### The Compressible-But-Not-Forecastable Theorem

**LLM dynamics are compressible but not forecastable.**

- **Compressible**: Δh_t ∈ R^2048 lies in a ~64D subspace → 20x I/O compression possible
- **Not forecastable**: z_{t+1} cannot be predicted from z_t using any linear operator → compute cannot be eliminated

This distinguishes two fundamentally different optimization targets:
1. **I/O compression**: Reduce data movement using the low-rank delta basis → viable
2. **Compute elimination**: Replace Transformer forward pass with prediction → not viable

### Why This Matters

The dominant paradigm in LLM optimization is **weight compression** (quantization, pruning, distillation). LKO reveals a different target: **state transition compression**. The heavy part is not the weights but the trajectory update.

### The Three Walls

| Wall | Cause | Status |
|------|-------|--------|
| MoE I/O | 5GB q4 data, random-access, SSD-bound | Requires MTLIO or tiered memory |
| DeltaNet Recurrence | 524K f32 scalar triple-loop | NEON-able but limited by 8GB |
| Attention Scaling | O(seq_len) scalar loop | Metal kernel exists, framework overhead dominates |

### Architecture Families

| Property | Family A (TinyLlama, Llama) | Family B (Qwen3.6, Mamba) |
|----------|---------------------------|---------------------------|
| Transport | h_{l+1} ≈ h_l (residual) | h_{l+1} ⟂ h_l (spherical) |
| Backbone | Attention (8.8x dominance) | GQA steering (sparse) |
| Safe collapse | 27% layer skip | Unknown (not testable) |
| DeltaNet role | N/A (Dense FFN) | Micro-steering (skip-able) |

## Part VII: Core Principles (Battle-Tested)

1. **LLM is not a homogeneous stack** — it is a phase-structured nonlinear dynamical system
2. **Uniform execution is wrong** — token, layer, and phase all demand different compute budgets
3. **LLM dynamics are compressible but not forecastable** — compress I/O, don't eliminate compute
4. **The hidden state is a phase point, not a state** — it rotates rapidly, cannot be cached as anchor
5. **Family A (Dense) and Family B (MoE/SSM) have fundamentally different optimization landscapes**
6. **Component verification ≠ system verification** — 40-layer q4 error accumulation defeats per-component correctness
7. **The bottleneck is execution topology, not compute** — MLX dispatch overhead dominates skip speedup
8. **What to compute ≠ how to compute** — the OS question is about allocation, not implementation
